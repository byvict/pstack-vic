# Pós-arm 0.4.14 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the local converge daemon own four post-arm cases that today stall in silence: a merge conflict with trunk, a comment or review posted after the verdict, a PR that stays armed or refused without moving, and a red trunk after a merge.

**Architecture:** `Pull` gains `mergeable`; the verdict gate gains one refusal for a `pre-pr` verdict (text posted after the verdict comment, other than the flow's own notes), so the arm, the sweep and the raiz classifier share it. The classifier maps that refusal to a new work kind, `respond`, maps every refusal a re-certification cures to `recertify`, maps a conflict to `recertify`, and marks two stalls (an armed PR that does not merge, the same refusal that does not clear). The raiz tick keeps one clock per stalled PR in `<stateDirectory>/waiting/` and holds the PR through the existing `hold()` when the clock passes its threshold; an outsider's text on a PR with work is held at once. A red trunk commit notifies once, recorded in `<stateDirectory>/red-trunk/`, from the post-merge pass (repositories with `postMerge`) or from the sweep tick at the trunk tip (repositories without it).

**Tech Stack:** Node 24 with type stripping, `node --test`; the fake GitHub (`fixtures/gh.mjs`) and fake `osascript` of `skills/poteto-mode/scripts/converge/fixtures/`.

**Spec:** [2026-09-30-pos-arm-design.md](../specs/2026-09-30-pos-arm-design.md), from the approved report `~/Dev/Skills/pstack-vic-runs/2026-09-30-pos-arm/relatorio.md`. The **Merge and progress** and **Local daemon** sections of [`converge-contract.md`](../../../skills/poteto-mode/references/converge-contract.md) must stay true to the code.

## Review Focus

1. **The flow's own comments.** A hold comment, a Raiz reply or a `@dependabot rebase` posted after the verdict must not start a `respond` loop; Victor's own comment under the same account must. Task 1 and Task 2.
2. **The sweep re-arming a PR it disarmed.** Text after the verdict must refuse the arm path too, not only disarm. Task 2, the sweep test on an unarmed PR.
3. **A stall clock that survives a change.** A new head, a different refusal, or a PR that stops being stalled must restart the clock. Task 4.
4. **Red trunk notifying on every tick.** The record must be written before the notification and read before the next one. Task 5.

## Rulings

One line per decision, then its cost if wrong. The numbering continues the notification plan (last was R106).

- **R107.** Version 0.4.14: PR #59 (`authorize.ts`) took 0.4.13 and was open and armed when this branch started. By R94, a PR that merges first moves the number; cost if wrong: one rebase and renumbering.
- **R108.** `mergeable` comes from `GET pulls/N` as `true`, `false` or `null`; an absent field reads as `null` (the list endpoint omits it), any other value is refused (`Invalid PR mergeable state`). `null` stays `idle`, since the read itself asks GitHub to compute it; cost if wrong: a conflict waits one interval (10 minutes) longer.
- **R109.** A conflict is `recertify` only on a PR whose base is trunk and whose `pre-pr` verdict the gate certifies, checked before the required checks. A stack child's conflict is with its parent, which its owner resolves; the sweep does not change, since a conflicted PR cannot merge; cost if wrong: a stack child in conflict stays idle.
- **R110.** Catch-up's `recertify` reads `gh pr view --json mergeable`; on a Dependabot PR in conflict it comments `@dependabot rebase` and ends `deferred`, as `repair` does for a stale base, because a push by the Raiz would take the branch from Dependabot; cost if wrong: a Dependabot PR that never rebases defers three times and is held.
- **R111.** Text after the verdict is a gate refusal for a `pre-pr` verdict, checked after the live PR and before the re-derivation: the arm refuses, the sweep disarms an armed PR and refuses to arm an unarmed one, and the classifier sees the same reason. A `converge` verdict keeps its fingerprint rule. Checking first also sends an injection comment to `respond`, where the Raiz names it, instead of to a re-certification that would publish over it; cost if wrong: a benign comment costs a full re-certification.
- **R112.** Counted: each issue comment and review comment by `created_at`, each review by `submitted_at` when it has a body or requests changes, at or after the second of the verdict comment's `created_at`, oldest first; the reason names the first (`Comment after the verdict by LOGIN`, `Review after the verdict by LOGIN`). GitHub's timestamps have one-second resolution, so a tie counts as after. An edit of an older comment does not count; cost if wrong: an edited comment that asks for a change goes unanswered, although the re-derivation still reads it for injection and claims.
- **R113.** A flow note is a comment by the authenticated account whose body starts with `<!-- converge:note -->`, `The local converge daemon ` (hold and post-merge comments from before 0.4.14) or `@dependabot ` (a command to Dependabot, whose parser wants the command first). The hold comment, the Raiz's replies in `respond` and Babysit's replies start with the marker. Any other text by the account is Victor's and counts; cost if wrong: Victor writing a comment that starts with one of the three prefixes goes unanswered.
- **R114.** `respond` joins `workKinds`, so the ledger, `outcome.json` and `run --kind respond` accept it. Catch-up lists the text as the gate counts it, triages each item against the code, fixes with a red-first proof or replies with a note, then certifies and delivers; cost if wrong: none found.
- **R115.** A `respond` item that needs a human decision ends the attempt `failed` with reason `needs a human decision: TOPIC`, and the existing cap holds the PR at the second failed attempt. A new outcome would change the ledger schema for a case the caps already cover; cost if wrong: one extra short attempt before the hold.
- **R116.** An outsider's comment, review comment or review on a PR with work is held at once, with a comment that says how to end it (delete the text, or list the login in `trustedAuthors`, then remove the label; hiding is not enough). An outsider author stays a silent skip (pstack-vic's Dependabot PRs by design); cost if wrong: an unlisted bot that comments on every PR holds every PR with work until Victor lists it.
- **R117.** Every gate refusal a re-certification cures is `recertify`: the three stale ones, a missing or superseded verdict comment, a comment by another author, identity or execution, another contract path. Only the races (`PR must be open and ready`, `PR head moved`) and a VERIFIED status from another account stay `skipped`; cost if wrong: a refusal a re-certification cannot cure repeats `recertify` until the failed cap holds.
- **R118.** The stall clock lives in its own file, `<stateDirectory>/waiting/<owner>-<repo>/<pr>.json` (`schemaVersion`, `repo`, `pr`, `head`, `key`, `since`), not in the ledger: clearing it is a removal with no read, so a PR without a stall never reads a file that could be corrupt. A different head or key restarts it, and the tick removes the clock of every PR no longer open right after it lists them, since nothing else visits a closed PR; cost if wrong: one more state directory.
- **R119.** Thresholds: an armed stall holds after 2 hours, the same refusal after 1 hour. Thirty CI runs each measured 4 to 8 minutes on pstack-vic (a 136-minute point was a rerun's second attempt) and 8.3 to 13.2 minutes on Clinext, so 2 hours is nine times the slowest run; after R117 only races are left to refuse, and they clear within a tick; cost if wrong: a PR slowed by a GitHub Actions backlog of more than 2 hours is held and needs its label removed.
- **R120.** Errors (a failed read, a snapshot limit) are not stalls: a GitHub outage would hold every PR. A certified PR the sweep does not arm (red trunk, missing protection) is not a stall either: a red trunk has its own notice (R122), and holding every PR through it would leave Victor removing labels one by one; cost if wrong: a PR that errors on every tick stays visible only in the log and `last-tick-*.json`.
- **R121.** The hold comment starts with the note marker, reads `Attempts: none` when the ledger has none, and an outsider hold adds how to end it; cost if wrong: none found.
- **R122.** A red trunk commit notifies once. The record `<stateDirectory>/red-trunk/<owner>-<repo>/<sha>.json` is written before the notification, so a failed write repeats next tick instead of the notification; a failed notification is an error and the record stays (R105). Two places look: the post-merge pass, for the commit its queue waits on (repositories with `postMerge`), and the sweep tick at the trunk tip (repositories without it, Clinext today, whose trunk went red at 11:31Z on 2026-09-30 with no one told). A cancelled push run counts as red, as the arm counts it; cost if wrong: a cancelled run notifies.
- **R123.** The trunk tip check costs one or two reads per sweep tick for a repository without `postMerge`, adds no error line for a red tip (the notice is the signal, and the sweep already refuses arms on a red trunk), and reports `redTrunk` beside `postMerge`; cost if wrong: none found.
- **R124.** `status` lists the stall clocks under `waiting`, beside the ledgers; a file that does not parse shows as its error; cost if wrong: none found.
