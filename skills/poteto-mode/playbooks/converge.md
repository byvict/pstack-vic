### Converge

Own one ready PR through an independent verdict, at most two repairs, merge and the resulting trunk Tests run. Read [the contract](../references/converge-contract.md) before dispatch or publication. Keep one parent per PR. Use [provider dispatch](../references/provider-dispatch.md) for every role and the existing runner unchanged. Resolve the forge once per [Opening a PR](opening-a-pr.md). The two Converge commands use GitHub directly.

1. **Pin the input.** Read `.cursor/converge.json` from the repository's current default branch. Record that full trunk SHA as `contract`, the PR merge base as `base`, the full head, and `git patch-id --stable` of the final unified base-to-head diff as `patch_id`. The reconciler obtains the same pinned objects through GitHub and writes no local refs. Stop on draft, closed, moved head, or any configured hold label. Reserve a unique local report path. A fresh verification pass gets a new persisted execution id, even when inputs match. A retry uses its original report. In explicitly authorized `verdict-only` proof runs, a hold permits steps 1 through 4 only. Preserve the hold. Proof status is always `error` and cannot authorize a merge.
2. **Classify.** Ordinary documentation and an authenticated Dependabot patch or minor npm update take `ci-only`. CI-only retains current-head CI and deterministic reconciliation and dispatches no model. Configured `surfaces` require a live user drive. Configured irreversible or contained risk paths also select `pr reviewer`. Money paths require reviewer proof. Empty, unreadable, unsupported or unmapped evidence never becomes a pass. The reconciler emits the selected lanes and features.
3. **Reconcile and dispatch.** Run `converge-reconcile --repo <owner/repo> --pr <n> --config .cursor/converge.json --output <unique-report.json>`. Add `--execution verdict-only` only for the authorized proof purpose. Prepare one exclusive lane directory per selected role with `prepare-lane.ts`, as documented in the contract. Dispatch `pr verifier` and the selected `pr reviewer` read-only through their resolved descriptors. Prompts contain the complete pinned verification skill, feature recipes, round identity, evidence prefix and output shape. Neither lane posts anything. Collect the original runner outputs and receipts. The publisher downloads actual Cursor artifact bytes and admits their identities and digests. No cloud-local path alone proves execution.
4. **Publish and end the turn.** Run `publish.ts --report <report.json> --evidence <owned-directory> --lane <manifest.json>` with one `--lane` per dispatched lane. Omit lanes for CI-only. The publisher revalidates the report, admits evidence and derives `VERIFIED`, `NOT VERIFIED` or `INCONCLUSIVE`. It posts a versioned JSON comment, then the exact-head `verdict` status with description `<verdict> by converge`. On successful CI-only the machine verdict is `VERIFIED` and `displayResult` is `CI-only`. Report the result and end this turn immediately. Do not fix, arm, label, rebase or dispatch another lane in this turn. On uncertain publication, preserve every handle and recover the existing comment and status before retrying. If recovery cannot establish whether the original turn ended, end the recovery turn too.
5. **Repair the first failed patch.** In a subsequent turn, reload GitHub and the trusted verdict history. For the first distinct failed patch, dispatch one `pr fixer, simple` when every finding is single-file, lint, type or a disproof. Use `pr fixer, complex` for all other findings, always for irreversible changes. Save launch intent and the original runner receipt before any retry. A lost launch response never permits another writer until the exact provider run is recovered as terminal or proved not launched. A fixer checks the live head immediately before its scoped push and reports the remotely confirmed new head. Return to step 1. A no-op repair consumes its repair opportunity and stops. An unchanged patch does not earn another failed-fix count or a new code verdict. Retain original code evidence only under the contract's unchanged-patch rule. Fresh current-head reconciliation and CI remain mandatory.
6. **Diagnose the second failed patch.** Dispatch the four `pr diagnosis pool` lanes read-only with both verdicts and receipts. Withhold the author's preferred diagnosis. Require two independently returned diagnoses to identify the same file, symbol, cause and mechanism. Two generic labels do not count. Dispatch one `pr fixer, complex` for that cause. Record the selected evidence and second repair attempt, then return to step 1. No consensus goes to step 7. INCONCLUSIVE waits for the named missing condition and spends no repair attempt.
7. **Hold after exhausted repairs.** On the third distinct failed patch, no consensus, a no-op repair or unknown writer outcome, add `needs-victor`. Post the trail with both diagnoses, receipts and evidence paths. End. While the label remains, no subsequent repair or merge action runs. Reconstruct the two-attempt budget from trusted prior rounds and owned fixer receipts after a restart. Never reset it because a new execution id exists.
8. **Arm and monitor.** In a later turn after a production VERIFIED publication, run `converge-arm --repo <owner/repo> --pr <n> --head <full-sha> --verdict VERIFIED`. Its single fail-closed chain reads trunk Tests health, live protection, the trusted exact-head verdict, then arms squash auto-merge with the full head match. `--dry-run` performs those reads and prints the four steps only when all pass. Poll `gh pr view --json state,mergedAt,headRefOid,mergeStateStatus,autoMergeRequest` plus live hold labels every two minutes for thirty minutes. Observe both labels and head on every poll. On a newly observed hold, invalid verdict, lost ownership or timeout, disable pending auto-merge before relinquishing ownership and report the actual outcome. If disarm is uncertain, notify the operator and retain the handle. DIRTY permits one `pr fixer, simple` rebase, recorded durably across restarts. Disarm before dispatch, then return to step 1. A changed patch requires new independent verification. GitHub's head match does not atomically check labels. The final reads and monitoring reduce this race but cannot eliminate it.
9. **Watch trunk after merge.** Identify the resulting push-to-trunk `Tests` run at the merged commit and watch its latest attempt. Green ends the run. Red before the next `04:00 America/Sao_Paulo` deployment deadline creates a ready revert through the resolved forge's `gh pr revert` semantics. Save creation intent, original PR, merged commit and returned revert URL. Recover uncertain creation by its exact forge identity before any retry. Converge the revert independently. The same green-trunk arm gate still applies. If trunk stays red, stop and notify the operator before the deadline. Never hide a trunk-health bypass in revert handling.
10. **Carry the feature map.** For every feature driven because the PR touches `surfaces`, require its feature document in the diff or the exact body line `skip: no user-visible change`. Missing travel is a documentary finding. The skip line exempts the document update only. It cannot skip the app drive, prove a claim or weaken any merge gate.

**Reply:** link the PR and verdict comment, name the exact head and execution, report the decision and evidence, repairs spent, current merge state, next control-flow step, retained handles and any missing condition. A proof run explicitly says that it cannot merge. Follow [show-me-your-work](../../show-me-your-work/SKILL.md) for the decision trail.
